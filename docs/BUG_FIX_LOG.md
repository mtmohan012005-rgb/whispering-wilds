## Bug Fix & Remediation Log (Master QA & Hardening)
**Date**: 2026-09-30  
**Target Engine**: Unity 6000.6.3f1 (45d8eee7de74)  
**Render Pipeline**: HDRP 17.7.0  
**Target Platform**: StandaloneWindows64

### [FIX-01] Player Ground Check Mathematics & Probe Offset
- **Subsystem**: Locomotion / Player Controller (`PlayerMovement.cs`)
- **Severity**: P0 (Locomotion Stability / Glitching)
- **Defect**:
  `groundedOffset` was configured as `-0.14f`, and the probe position was calculated as `transform.position.y - groundedOffset`. Because `y - (-0.14f) = y + 0.14f`, the ground detection sphere was centered 14cm *above* the CharacterController feet pivot instead of at ground level. Furthermore, `groundLayers` was set to `~0` (all layers), causing false positive grounding against NPCs, trigger volumes, and interactive props.
- **Remediation**:
  1. Corrected sphere probe center to `transform.position.y + groundedOffset` with `groundedOffset = 0.15f` and `groundedRadius = 0.28f`, ensuring the sphere spans through and below the character feet.
  2. Implemented explicit layer masking: automatically strips `1 << gameObject.layer`, `Ignore Raycast`, `UI`, and `Water`.
  3. Combined `Physics.CheckSphere` with `CharacterController.isGrounded` for seamless slope and stair locomotion.
  4. Added `OnDrawGizmosSelected` visual debugging in Scene view.

### [FIX-02] HDRP Dynamic Resolution Scaling Enablement
- **Subsystem**: Graphics / Quality Governor (`HDRP Balanced.asset`, `HDRP Performant.asset`, `HDRP High Fidelity.asset`)
- **Severity**: P0 (Performance / Rendering Pipeline)
- **Defect**:
  `GraphicsPerformanceManager.cs` called `ScalableBufferManager.ResizeBuffers()` to dynamically scale render scale under frame pressure, but `dynamicResolutionSettings.enabled` was hardcoded to `0` (false) across all three HDRP quality profile assets. Consequently, Unity HDRP ignored all dynamic buffer resize requests.
- **Remediation**:
  Updated `dynamicResolutionSettings.enabled: 1` in `HDRP Balanced.asset`, `HDRP Performant.asset`, and `HDRP High Fidelity.asset`. Dynamic buffer scaling now directly reduces GPU fillrate under frame pressure.

### [FIX-03] HDRP Volume Atmospheric Fog & Weather Overrides
- **Subsystem**: World / Atmospheric Simulation (`WeatherSystem.cs`)
- **Severity**: P1 (Rendering Conflict / Visual Integrity)
- **Defect**:
  `WeatherSystem.cs` directly set `RenderSettings.fogDensity` and `RenderSettings.fogColor`. In HDRP 17, `RenderSettings.fog` is bypassed by the HDRP volume framework, causing weather fog transitions to have inconsistent or broken atmospheric rendering.
- **Remediation**:
  Integrated `UnityEngine.Rendering.HighDefinition.Fog` volume overrides. `WeatherSystem` now dynamically queries the active global/scene `Volume` profile, acquires the HDRP `Fog` component, and modulates `fog.albedo.value` and `fog.meanFreePath.value` smoothly during weather shifts, maintaining `RenderSettings` only as fallback.

### [FIX-04] Safe Additive Regional Scene Streaming & Transition Flow
- **Subsystem**: World Streaming (`RegionalSceneManager.cs`, `TamilNaduGeography.cs`)
- **Severity**: P1 (Scene Loading / State Integrity)
- **Defect**:
  `RegionalSceneManager.cs` claimed additive scene streaming in comments, but executed `SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Single)`. If an invalid region was requested, it silently caught the error and fell back to Chennai without notifying callers. It also called aggressive `GC.Collect()` twice sequentially during load.
- **Remediation**:
  1. Added `TamilNaduGeography.TryGetRegion()` and `IsValidRegion()` for strict pre-transit validation.
  2. Implemented true additive streaming: preloads target region additively, validates completion, sets active scene, moves CharacterController safely to validated spawn point, rebinds camera, unloads old scene additively, and triggers controlled boundary cleanup without synchronous GC stalls.
  3. Added `OnRegionLoadFailed` error propagation instead of silent fallback.

### [FIX-05] Boot Scene Input System & Manager Initialization
- **Subsystem**: Core / UI Architecture (`BuildBootScene.cs`, `00_Boot.unity`)
- **Severity**: P1 (Input Compatibility / Startup Reliability)
- **Defect**:
  `00_Boot.unity` generated by `BuildBootScene.cs` used the legacy `StandaloneInputModule` on `EventSystem` despite the project using the new Unity Input System (`com.unity.inputsystem`). In addition, persistent manager singletons (`GameManager`, `WorldTimeSystem`, `QualityManager`, etc.) were not instantiated in `00_Boot.unity`.
- **Remediation**:
  1. Replaced `StandaloneInputModule` with `UnityEngine.InputSystem.UI.InputSystemUIInputModule`.
  2. Added `SetupPersistentManagers()` in `BuildBootScene.cs` so all core persistent singletons (`[--- MANAGERS ---]`) initialize cleanly at application startup.

### [FIX-06] NPC 11-State FSM, Occupations & Throttled AI Tiers
- **Subsystem**: AI / Crowd Simulation (`NPCCharacter.cs`, `NPCScheduleManager.cs`, `NPCPerformanceTierManager.cs`, `NPCState.cs`)
- **Severity**: P1 (Living World Authenticity / CPU Performance)
- **Defect**:
  NPCs lacked physical occupation behaviors; schedules merely printed log messages while NPCs stood static. `NPCPerformanceTierManager` only modified `animator.cullingMode` without throttling expensive pathfinding, raycasts, or state updates.
- **Remediation**:
  1. Defined formal 11-state FSM (`Idle`, `GoToTarget`, `Working`, `Interacting`, `Talking`, `Resting`, `Eating`, `Socializing`, `ReturningHome`, `Sleeping`, `Interrupted`).
  2. Implemented real occupation routines (Farmer tending `FarmPlot`, Fisherman, TeaWorker plucking foliage, Shopkeeper, Elder).
  3. Upgraded `NPCPerformanceTierManager` to execute throttled AI ticks (Near: 10Hz, Medium: 3Hz, Far: 0.5Hz, Hibernating: 0.1Hz) and staggered distance evaluations in round-robin batches across frames.

### [FIX-07] Discrete Production Retail vs. QA Benchmark Build Pipelines
- **Subsystem**: Build Pipeline Automation (`BuildPipelineAutomation.cs`)
- **Severity**: P1 (Release Engineering)
- **Defect**:
  Automated build scripts bundled all 12 scenes (including the 4 benchmark test scenes) into the standard release build.
- **Remediation**:
  Created two distinct build entry points:
  1. `BuildProductionWindows()`: Bundles only the 8 authored gameplay scenes (`00_Boot` through `07_Nilgiris_Sanctuary`) to `Build/Windows/TheWhisperingWilds.exe`.
  2. `BuildQABenchmarkWindows()`: Bundles the 8 gameplay scenes + 4 benchmark scenes to `Build/Windows_QA/TheWhisperingWilds_QA.exe`.
  3. Generates structured `BUILD_REPORT.json` metadata upon completion.
